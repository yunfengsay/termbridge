# ADR-0013: 手表作为低风险 Action Remote

- 状态: 采纳
- 日期: 2026-09-05

## 背景

T-Rex 3 的圆形 480 px 屏幕不适合复制手机的 Agent Dashboard；Zepp Recorder 也不提供实时输入振幅，
因此伪造波形既占空间又传达错误状态。手表真正有价值的时刻，是用户离开电脑后收到 Agent 的关键变化，
快速判断是否需要回到手机或电脑，以及对低风险下一步给出明确意图。

## 决策

手表首屏只保留通知工作箱和 Global 语音，完整 Agent List 放二级页。通知按需关注、运行、完成的优先级与
发生时间排序；详情页按真实状态提供摘要、检查后重试、继续、停止、稍后 30 分钟和手机接力。

Zepp Side Service 只调用 Android 私有 loopback API。每次动作有独立 ID，Android 用既有
`brain_send`/Execution Event 流执行固定自然语言策略，并把 queued、thinking、done 或 error 回执返回手表。
若用户停止等待，手表只停止轮询并明确提示动作可能仍在执行。

手表不能提交任意 Prompt 或命令，也不能批准部署、删除、授权等后果性操作。待批准状态只能获取摘要、
稍后、停止或将准确 Session 接力到手机；用户在那里查看完整上下文后再决定。Android Watch Hub 管理通知
路由、配对诊断和动作/语音历史；macOS 菜单栏控制中心读取 Host 权威上下文并打开准确的 Herdr/PTY 会话。

## 后果

手表成为通知分类、状态确认和低风险遥控器，而不是缩小的终端。动作路径可审计、可轮询、有明确失败态，
且手机/电脑仍是高后果决策的最终界面。代价是 Zepp 通知镜像和开发者预览仍依赖官方 Zepp 手机 App，
物理手表安装不能由 Android ADB 替代。
